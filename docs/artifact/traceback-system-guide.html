같은 전체 탈퇴 API, 세 가지 인증 수단

위 04번 경로를 계정별로 펼친 그림

세 경로의 공통 결과: soft delete

User 행은 삭제하지 않습니다. is_active=False, deleted_at 설정, 이메일·사용자명 익명화, 비밀번호 사용 불가 처리를 합니다. EmailAddress와 SocialAccount 행은 실제로 삭제하고, 커밋 뒤 UserSession.end()를 호출합니다. 따라서 계정 행 보존과 로그인 연결 정보 삭제를 구분해야 합니다. 그림의 ACTIVE·DELETE_PENDING·DELETED는 개념적 단계 이름이며, User.status 컬럼을 새로 만들기로 결정했다는 뜻은 아닙니다. DELETED도 User 행이 사라진다는 뜻이 아닙니다.

전체 탈퇴와 “Kakao 연결만 해제”는 무엇이 다른가요?

전체 탈퇴는 세 경우 모두 DELETE /accounts/delete를 거쳐 User를 soft delete합니다. 연결만 해제하는 allauth provider API는 User와 이메일 로그인을 유지하고 SocialAccount만 삭제합니다. Kakao 전용 계정은 비밀번호가 없어 마지막 로그인 수단을 끊지 못하도록 allauth가 400 no_password로 거절합니다. 현재 validate_disconnect()에서 원격 unlink를 먼저 실행하는 부분 실패 위험은 전체 탈퇴와 별도로 고쳐야 합니다.

현재 동작 근거: services.py 19–55행, models.py 56–68행, views.py 46–60행, test_auth_views.py 156–220행. 개선안의 상태·작업 행은 아직 없습니다. 실패 경계와 Kakao API의 재시도 조건은 인증 결정 가이드에서 이어집니다.

Delivery · source to running container

두 번 검증하고, 한 번 만든 이미지를 승격합니다

feature PR은 코드를 검증하고, development push가 이미지를 ECR에 올립니다. main은 새 이미지를 만들지 않고 development에서 배포에 성공한 digest를 사용합니다. 각 단계를 눌러 실행 조건과 실제 코드를 볼 수 있습니다. 코드 상자는 핵심 부분을 축약한 것이며 원본 파일로 이동할 수 있습니다.

코드 변경→CI 검사→이미지 게시→서버 배포→외부 확인
CI가 녹색이면 실제 서버 배포까지 끝났나요?

CI는 코드와 임시 테스트 환경의 검증입니다. 배포 job이 실행되고, 서버가 이미지를 받아 실행하고, 외부 HTTPS 요청이 통과해야 실제 서비스 검증이 끝납니다. 아래 TRACEBACK 단계에서 각 상태를 따로 확인합니다.

SHA가 두 종류처럼 보이는 이유는 무엇인가요?

uses: ...@SHA는 다른 저장소에서 가져오는 GitHub Action 코드의 버전을 고정합니다. github.sha는 이번에 검사·배포하는 TRACEBACK 소스의 커밋입니다. ECR의 @sha256:…은 그 소스로 만든 컨테이너 이미지 내용을 가리킵니다. 이름은 비슷하지만 식별 대상이 각각 다릅니다.

① DNS → EIP · 확인됨API 이름이 개발 EC2 주소를 찾음 ② EC2·DB 준비 · 일부만 완료ECR pull·Docker 준비됨. 앱 DB 사용자·런타임 .env 대기 ③ Nginx HTTP 완료 · TLS 대기외부 API 443 연결 거부. 인증서·443 프록시 필요 ④ Vercel → 인증 · 미검증origin 재배포 완료. API HTTPS 뒤 브라우저 QA
도구 버전 · 외부 저장소Action 커밋 SHA

uses: astral-sh/setup-uv@…의 SHA는 CI가 실행할 외부 Action 코드입니다. 우리 앱 버전이 아닙니다. version: 0.10.4는 설치할 uv 프로그램 버전입니다.

소스 버전 · TRACEBACK앱 커밋 SHA

GitHub push의 github.sha입니다. development 배포에서는 이 값을 ECR 이미지 태그로 사용합니다. 운영에서는 릴리스 merge commit의 두 번째 부모가 개발 원본 SHA입니다.

이미지 내용 · ECRimage digest

@sha256:…은 빌드된 이미지 내용을 식별합니다. 개발 EC2와 운영 EC2가 이 동일한 digest를 실행합니다.

workflow_call은 ci.yml의 main push 배포 job이 호출합니다. concurrency로 운영 배포를 직렬화하고 진행 중 실행을 취소하지 않습니다.

actions: read는 과거 개발 CI 실행을 조회하는 데 필요합니다. id-token: write는 OIDC용입니다. environment: production은 GitHub에서 운영 변수와 승인 규칙을 가져옵니다. 승인자는 YAML이 아니라 GitHub 설정에 지정해야 합니다.

checkout의 fetch-depth: 0은 merge commit 부모를 읽을 전체 이력을 받습니다. OIDC로 운영 배포 역할을 인수하되 운영 역할에는 ECR push 권한이 없어야 합니다.

030–045릴리스 merge commit에서 개발 원본 SHA 확정코드와 해설

GitHub 원본 30–45행

BEFORE_SHA는 이번 push 이전 main 커밋입니다. HEAD^1이 그것과 같아야 main에 merge commit 하나가 추가된 형태입니다.

HEAD^2는 병합 당시 development 쪽 부모, 즉 개발 서버에서 검증했어야 할 소스 커밋입니다. 현재 움직이는 development 브랜치를 다시 조회하지 않습니다. 부모가 없거나 예상한 병합 구조가 아니면 배포 전에 실패합니다.

30      - name: Resolve image deployed to development31        id: image32        env:33          AWS_REGION: ${{ vars.AWS_REGION }}34          BEFORE_SHA: ${{ github.event.before }}35          ECR_REPOSITORY: ${{ vars.ECR_REPOSITORY }}36          GH_TOKEN: ${{ github.token }}37        run: |38          source_sha="$(git rev-parse --verify HEAD^2 2>/dev/null)" || {39            echo "Production release must use a merge commit." >&240            exit 141          }42          if [ "$(git rev-parse --verify HEAD^1)" != "$BEFORE_SHA" ]; then43            echo "Production release must be one merge commit on main." >&244            exit 145          fi

065–074ECR SHA 태그를 동일 digest URI로 변환코드와 해설

GitHub 원본 65–74행

ECR 저장소가 IMMUTABLE인지 다시 확인하고, 개발 원본 SHA 태그의 imageDigest를 조회합니다. digest가 비었거나 None이면 중단합니다.

현재 AWS 계정 ID·리전·저장소·digest를 합쳐 steps.image.outputs.uri로 내보냅니다. 운영은 이 URI를 받아 이미지를 새로 빌드하지 않습니다.

65          tag_policy="$(aws ecr describe-repositories --repository-names "$ECR_REPOSITORY" --query 'repositories[0].imageTagMutability' --output text)"66          test "$tag_policy" = IMMUTABLE67          digest="$(aws ecr describe-images \68            --repository-name "$ECR_REPOSITORY" \69            --image-ids "imageTag=$source_sha" \70            --query 'imageDetails[0].imageDigest' --output text)"71          test -n "$digest"72          test "$digest" != None73          account_id="$(aws sts get-caller-identity --query Account --output text)"74          echo "uri=${account_id}.dkr.ecr.${AWS_REGION}.amazonaws.com/${ECR_REPOSITORY}@${digest}" >> "$GITHUB_OUTPUT"
