02 · BSON

객체는 Network에서 어떤 모습일까?

BSON과 Wire protocol은 같은 말이 아닙니다. BSON은 Document 표현 형식이고, Wire protocol은 그 BSON을 담아 주고받는 message 규칙입니다.

별도 직렬화 실험 · 주문 DOCUMENT
{ _id: 1001,
  customerId: 7,
  status: "PAID",
  items: [ ... ], total: 37000 }
→
DRIVER · BSON BYTES
ed000000 10 5f696400 e9030000
10 637573746f6d65724964 ...

전체 길이: 237 bytes

구분: 위 237 B는 Lab에서 BSON.serialize(order)로 주문 Document 전체를 직렬화한 결과입니다. 앞의 find 요청은 주문 전체가 아니라 Command와 Filter를 BSON으로 보냅니다.

BSON: 길이와 Type 정보가 들어 있는 Binary Document 형식. OP_MSG: 현대 MongoDB 요청·응답의 표준 Wire message 형식. OP_MSG body section에 BSON command object가 들어갑니다.

03 · QUERY

mongod는 요청을 어떻게 실행으로 바꿀까?

“MongoDB frontend”는 별도 process 이름이 아니라 mongod 안의 network·command·query 책임을 묶어 설명한 개념 경계입니다.

COMMANDMessage 해석

Database와 Collection, find·insert 같은 Command를 식별

RULES검증

권한·session·transaction metadata를 확인하고, 쓰기 요청이면 설정된 Document validator를 적용

PLANNERAccess path 선택

Collection scan과 사용할 수 있는 Index 후보를 평가

EXECUTIONPlan 실행

선택된 Plan이 WiredTiger에 Record·Index 작업 요청

선택된 Indexcustomer_status
검사량1 key · 1 document
결과1 document 반환
Driver command monitoring에서 확인한 Command
create → createIndexes → insert → update → commitTransaction → find

Command monitoring은 Driver가 Command를 시작하는 경계를 보여주며 raw packet capture를 대신하지는 않습니다.
