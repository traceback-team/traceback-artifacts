01 · WHY

RDBMS가 잘하는데도 왜 다른 Database가 필요했을까?

RDBMS가 부족해서가 아니라, 대규모 서비스의 핵심 요구가 관계·범용 질의 이외의 방향으로도 넓어졌기 때문입니다.

일반 개념 · 특정 제품의 저장 엔진과 분리

출발점 · RDBMS

Table, 관계, Constraint(허용할 데이터 규칙), Transaction(여러 변경을 한 단위로 처리)을 Database가 관리합니다. 여러 Table을 Join(공통 값으로 결합)하고 관계를 정확히 지키는 범용성이 큰 강점입니다. 이 강점은 지금도 유효하며 NoSQL이 RDBMS를 대체하지 않았습니다.

규모데이터·트래픽이 여러 서버로 증가한 장비를 키우는 것만으로 감당하기 어려워짐
모양중첩 객체와 자주 달라지는 FieldTable을 나누고 구조를 바꾸는 비용이 커질 수 있음
질문ID 조회·데이터 묶음·관계 경로의 반복범용 결합보다 특정 읽기 방식이 훨씬 중요해짐
→
RDBMS가 불가능해서가 아님관계형 모델의 범용성에 드는 비용

Table 결합, 구조 변경, 데이터를 여러 서버로 나누는 설계가 핵심 요구에 비해 복잡해질 수 있습니다.

→
NOSQL의 선택주된 질문에 맞는 모델을 먼저 선택

자주 하는 읽기와 분산 방식을 Database의 기본 데이터 모양으로 직접 표현합니다.

그래서 나온 선택: 2000년대의 대규모 인터넷 서비스는 수천 대 서버로 확장되는 저장과, 일부 서버가 고장 나도 서비스를 계속하는 높은 가용성을 요구했습니다. Google Bigtable과 Amazon Dynamo는 각각 대규모 분산 데이터와 식별자(Key)로 값을 찾는 저장을 위한 설계를 보여주었습니다. 이후 NoSQL은 관계형 Table 이외의 데이터 모델을 중심에 둔 여러 Database 계열을 묶어 부르는 이름이 되었습니다.

NOSQL이 잘 맞는 경우

주요 접근 방식이 분명하다

  • 함께 읽고 갱신하는 업무 데이터 묶음을 한 단위로 다룬다.
  • Document(필드 묶음)마다 구성이 다르거나 자주 변한다.
  • 특정 Key를 기준으로 데이터를 여러 서버에 나눠야 한다.
RDBMS가 잘 맞는 경우

관계와 범용 질의가 중심이다

  • 여러 종류의 데이터를 다양한 방식으로 결합한다.
  • Database의 규칙으로 Table 사이 관계를 강하게 지킨다.
  • 정형화된 구조와 복잡한 다중 변경 처리가 핵심이다.
현대 RDBMS와 MongoDB의 경계가 겹치는 이유

현대 RDBMS도 JSON·분산 기능을 제공하고 MongoDB도 Schema validation, Index, $lookup, ACID transaction을 제공합니다. 차이는 기능의 유무보다 기본 모델과 최적화의 중심입니다.

02 · DIFFERENCE

같은 주문을 RDBMS와 MongoDB는 어떻게 다르게 다룰까?

_id: 1001 주문을 구성하는 데이터가 어디에 놓이고, 읽을 때 어떤 작업이 필요한지를 같은 구도로 비교합니다.

RDBMS 일반 모델 ↔ MongoDB Document 모델
RDBMS의 기본 관점

관계를 정규화한 Table

ordersid · customer_id · status · total
order_itemsorder_id · sku · qty · price
addressescustomer_id · city · postal_code
여러 Table의 Row→ 공통 ID로 결합 →주문 결과 조립

중복을 줄이고 관계를 Database 규칙으로 지키며, 다양한 방식으로 다시 조합하기 좋습니다.

↔
MONGODB의 기본 관점

Aggregate를 한 Document로

orders / _id: 1001customerId · address {…}
items [{…}] · status · total
하나의 Document→ 식별자 _id로 조회 →주문 묶음 반환

Aggregate는 함께 읽고 갱신하는 업무 데이터 묶음입니다. 한 번에 읽기 쉽지만 다른 Aggregate와의 중복·관계는 별도로 설계해야 합니다.

핵심 차이는 Schema(데이터 구조 규칙)가 있느냐가 아니라 데이터 경계를 어디에 두는가입니다. RDBMS는 관계를 보존한 뒤 필요할 때 조합하고, MongoDB는 함께 사용하는 데이터를 Document 경계 안에 모으는 선택을 우선합니다.

Document 외의 NoSQL은 어떤 질문에 맞춰졌을까?
