01 · BOUNDARY

논리 구조와 물리 구조는 어디서 갈라질까?

사용자가 보는 이름과 Storage engine이 관리하는 구조는 같은 층이 아닙니다.

MongoDB 논리 계층 ↔ WiredTiger 물리 계층

번역 →
PHYSICAL · WIREDTIGER / OS

Key·Value와 bytes의 세계

WiredTiger Table / B-tree

Collection data와 각 Index의 구조

Record

Record key와 BSON value bytes

Internal / Leaf Page

Cache에서 탐색·변경되는 B-tree 단위

.wt block · Journal record

압축된 Page block과 복구 기록

정확한 표현: WiredTiger는 “아무것도 모르는” 것이 아니라 업무 의미를 모릅니다. Key·Value, B-tree, Page, timestamp와 압축은 알지만 그 bytes가 주문의 배송지인지 판단하지 않습니다.

02 · PAGE

Document는 어떻게 파일 bytes가 될까?

Document 하나가 Page 하나가 되는 것이 아닙니다. 여러 Record가 B-tree Page에 놓이고, memory의 변경된 Page가 disk image로 조정됩니다.

MONGOD OUTPUTRecord operation

Collection·Index key/value 읽기·쓰기

BTREEInternal / Leaf Page

Key를 따라 leaf의 Record에 접근

MEMORYWiredTiger Cache

Page를 읽고 변경 상태 유지

RECONCILECompress / Block

변경을 on-disk Page image로 생성

OS / DISK.wt file bytes

Collection·Index별 파일과 metadata

ed000000 10 5f696400 e9030000 10 637573746f6d65724964 ...

주문 BSON은 237 bytes였습니다. 첫 4 bytes의 little-endian 값 0x000000ed도 전체 길이 237을 뜻합니다.

03 · MECHANISMS

Index·Transaction·WAL은 어느 층에 있을까?

사용자가 선언하는 논리 기능과 WiredTiger의 물리 메커니즘이 협력합니다.

INDEX

별도 B-tree 탐색 구조

Query: customerId=7, status=PAID
mongod Planner가 customer_status 선택
WiredTiger Index key → Record

Index 정의·Plan 선택은 mongod, Index Page·파일 갱신은 WiredTiger 책임입니다.

TRANSACTION

여러 변경을 한 단위로 Commit

Session + txnNumber 3
Alice −15,000 · Bob +15,000
commitTransaction → 둘 다 공개

한 Document 쓰기는 원자적입니다. 여러 Document를 모두 적용하거나 취소할 때 transaction을 사용합니다.

WAL / JOURNAL

Data Page보다 먼저 복구 기록

Data + Index 변경
WiredTiger Journal record
Checkpoint 이후 오래된 Journal 정리

Crash 후 마지막 checkpoint 이후 변경을 재생하기 위한 write-ahead log입니다.

WiredTiger Journal

한 mongod의 local crash recovery용 log.

Replication Oplog

Replica set member 사이의 논리 변경 복제용 log. Journal과 목적·소비자가 다릅니다.
