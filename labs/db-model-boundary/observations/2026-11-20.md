## Client에서 관찰한 지연

단위는 millisecond입니다. 각 요청에는 Driver와 로컬 Docker Network 비용이
포함됩니다.

| 작업 | PostgreSQL 정규화 median / p95 | PostgreSQL JSONB median / p95 | MongoDB Document median / p95 |
|---|---:|---:|---:|
| 주문 Aggregate 조회 | 0.284 / 1.294 | 0.159 / 0.235 | 0.419 / 0.658 |
| 고객·상태별 조회 | 0.189 / 0.286 | 0.214 / 0.507 | 0.656 / 1.119 |
| 상태 한 Field 수정 | 0.916 / 3.055 | 0.912 / 2.941 | 2.066 / 3.725 |
| 항목 수량 하나 수정 | 0.609 / 2.513 | 0.394 / 0.859 | 1.060 / 2.811 |
| SKU가 포함된 주문 수 | 0.103 / 0.183 | 0.267 / 0.401 | 0.558 / 1.331 |

이 수치는 제품 성능 순위가 아니다. Driver·Wire Protocol·Binary Format과
내구성 구현이 다르고 측정 시간이 짧다. 이 환경에서는 JSONB의 한 Row 조회가
정규화 모델의 세 Index Scan과 JSON 조립보다 짧았고, SKU 횡단 집계에서는
정규화 모델의 Index Only Scan이 가장 짧았다.

## 실행 계획에서 확인한 비용 이동

### 주문 `_id: 1001` Aggregate 조회

- 정규화: `orders_norm`, `order_shipping_norm`, `order_items_norm`의 Index Scan,
  Nested Loop, Sort, Aggregate. Shared Buffer hit `13`.
- JSONB: `orders_jsonb_pkey` Index Scan 하나. Shared Buffer hit `4`.
- MongoDB: `IDHACK`, Key `1`, Document `1` 검사.

### `SKU-1033`이 포함된 주문 수

- 정규화: `norm_items_sku` Index Only Scan, Index entry `75`, Shared Buffer hit `5`.
- JSONB: `jsonb_items_gin` Bitmap Index Scan이 후보 `131`개를 만들고 Heap에서
  실제 주문 `75`개를 확인. Shared Buffer hit `83`.
- MongoDB: `items_sku` Multikey Index로 Key `75`, Document `75` 검사.

Aggregate를 한 값으로 저장하면 한 주문을 조립하는 경로가 짧아졌지만, 배열
내부 값을 여러 주문에 걸쳐 집계할 때는 더 많은 후보와 Document를 확인했다.

## 적재 후 저장 크기

| 모델 | Data | Index | 합계 |
|---|---:|---:|---:|
| PostgreSQL 정규화 | 11.73 MiB | 13.05 MiB | 24.79 MiB |
| PostgreSQL JSONB | 21.35 MiB | 9.20 MiB | 30.55 MiB |
| MongoDB Document | 3.43 MiB | 5.48 MiB | 8.91 MiB |

MongoDB 값은 WiredTiger의 압축된 `storageSize`와 `totalIndexSize`다. PostgreSQL
값은 `pg_table_size`와 `pg_indexes_size`다. 따라서 이 차이는 데이터 모델뿐
아니라 BSON·JSONB 표현, Page 구성, Snappy Compression까지 합쳐진 결과다.

## 이 실험으로 말할 수 없는 것

- Production 처리량이나 제품 전체 성능 순위
- Cold Cache와 실제 SSD/HDD I/O 비교
- Sharded Cluster, Failover, Cross-shard Transaction 비용
- 장시간 Update 뒤 Bloat·Compaction·Vacuum 비용
- 동시 사용자 수가 증가할 때의 Lock·Connection pool·Cache 경쟁
- InnoDB 성능. InnoDB는 발표의 물리 구조 비교에만 사용한다.
